# Windows 1.4.8 类型筛选列表滚动

真实操作确认“全部”列表滚动正常，而文字、文件和图片筛选列表持续不顺。由此排除统一滚轮曲线，并把问题收敛到筛选后的列表状态。

同一套 1000 条合成记录、相同滚轮曲线和行程下，筛选前后各重复 5 次：

| 状态 | 滚动期间分配量 | UI 最慢响应中位数 | 超过 33.3 ms 的 UI 阻塞 |
| --- | ---: | ---: | ---: |
| 全部 | 12.2–12.4 MB | 5.39 ms | 0 |
| 筛选后，旧虚拟容器保留 | 44.8–48.6 MB | 8.55 ms | 0 |
| 筛选后，清理一次旧虚拟容器 | 14.8–16.5 MB | 8.33 ms | 0 |
| 再复用行位图缓存 | 12.0–12.2 MB | 3.32 ms | 0 |

筛选后的额外分配来自 WPF 沿用筛选前的虚拟化容器状态。产品现在只在用户实际切换记录类型时清理一次旧视觉容器，然后由现有回收虚拟化按新结果重新建立可见行。数据集合没有 Reset，历史记录没有重建或修改；选择保留、回到顶部、搜索组合和筛选动画规则保持不变。

回收行重新进入视口时会继续使用 DPI 匹配的现有 `BitmapCache`，不再反复创建相同缓存。图片缩略图命中内存缓存时也会同步绑定，省去重复的取消令牌和异步任务；首次出现且未缓存的图片仍在后台限流解码。

图片筛选场景重复 5 次后的回调最大值为 `14.26–16.96 ms`，分配量为 `12.7–13.0 MB`，没有长停顿。`--ui-performance-test` 66 项全部通过。

类型切换的列表蒙层按顶部选中块的移动距离做感知归一：相邻类型使用较低强度、较长的淡出；距离越远逐步回到原有 `45% / 120ms`，因此“全部 ↔ 图片”的既有效果不变。这里只调整无子元素的视口蒙层，不对列表内容树添加位移或透明度动画。

本版保留 1.4.7 默认的连续滚轮曲线，不采用整格瞬移，也不把快速预设设为默认。自动探针不等同于真人手感，最终仍以覆盖安装后的实体鼠标验证为准。
