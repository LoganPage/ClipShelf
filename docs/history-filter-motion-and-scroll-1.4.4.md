# Windows 1.4.4 历史筛选动画与滚动复测

在 12 个场景、每个场景 5 次的最终测量中，卡顿没有稳定出现：全部 60 次滚动/动画样本均未出现 `callbackIntervalMs.max > 33.3 ms` 或停顿。按预先固定的门槛，本轮结论是**未复现**，因此没有修改产品滚动逻辑。

## 筛选动画

类别切换仍使用原有的 Y `18 → 0`、opacity `.6 → 1`、240 ms、`SineEase/EaseInOut` 动画参数，但动画目标由整个 `HistoryBorder` 改为列表内部的 `ScrollContentPresenter`（不兼容时安全回退到 `ItemsPresenter`）。记录内容上移淡入时，外框、边框、圆角与滚动条保持静止。类型筛选回归测试新增了外框变换、透明度和窗口内边界均不变的断言。

最终 `filter-animation` 的 5 次 callback max 为 `16.33 / 17.53 / 17.52 / 16.73 / 16.64 ms`，中位数 `16.73 ms`，停顿数均为 0。

## 判定与问题回答

1. **没有稳定复现。** 任一场景 5 次中异常次数都是 0，未满足“同一场景至少 3 次异常”的第一条门槛；无筛选无置顶对照同样为 0。
2. **没有可定位的停顿阶段。** 所有 `stallCount` 都为 0，因此不能声称集中在正向、反向或方向翻转处。若以后出现停顿，原始样本会直接记录包序号和方向。
3. **细分包略慢但没有停顿。** 合成筛选置顶场景的 callback max 中位数从整数包 19.08 ms 增至细分包 23.39 ms（+4.31 ms）；真实副本从 21.37 ms 增至 23.15 ms（+1.78 ms）。两者仍低于 33.3 ms。
4. **真实数据与合成夹具差异较小。** 整数反向场景的中位数分别为 21.37 ms 和 19.08 ms，真实副本高 2.29 ms；不足以构成稳定卡顿证据。
5. **置顶在首屏外没有更差。** 首屏内为 21.37 ms，首屏外为 19.66 ms；本轮数据不支持“遇到离屏置顶项才卡”的假设。
6. **无法把用户感知归因到 1.4.3 的某处改动。** 当前协议没有复现，且筛选/置顶、无置顶及对照分布重叠；继续指定某段滚动代码会是无证据猜测。
7. **变更前后指纹不同。** 1.4.3 与本轮 1.4.4 指纹见上，但本轮没有滚动产品修复，也没有“修复后性能提升”的结论。

上一轮 prompt-36 §3.D 所写的“已复现 / 已修复”来自单次采样，现更正为：**单次结果不足以成立；在固定门槛和 5 次重复协议下未复现。** 这不等于用户感知不存在。若要进一步复现，需要用户补充卡顿时的记录总数、所选类型、置顶条数、滚动方向、鼠标或触控板型号、是否打开设置面板、同时运行的程序，以及卡顿持续多久。
